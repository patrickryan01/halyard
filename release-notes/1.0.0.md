# Halyard 1.0.0

One release with everything in it.

## What is in it

* Google (Gmail API, OAuth, labels, threads, history sync, People contacts), Microsoft 365 and Outlook.com (Graph, OAuth, folders, delta sync, contacts), and self-hosted mail (IMAP with IDLE and SMTP, JMAP) as plugins behind one interface.
* Conversation threads, full text search with `from:`, `to:`, `subject:`, `is:unread`, `is:starred` and `has:attachment`, labels and folders, archive, delete, spam, snooze, undo send, drafts, a rich composer with attachments and drag and drop, signatures, a unified inbox, Gmail's keyboard shortcuts, desktop notifications, an offline cache with queued actions, contacts autocomplete, light and dark themes, and account setup from one field.
* A read and write MCP server, on by default, covering every account: 37 tools for accounts, folders, threads, search, send, reply, forward, drafts, the outbox, labels, archive, delete, snooze, attachments in and out, contacts, and settings. It needs a bearer token from the data directory and serves loopback only.
* Packages: Arch (`halyard-1.0.0-1-x86_64.pkg.tar.zst`), EmberRTOS Desktop (openSUSE Tumbleweed, `halyard-1.0.0-0.x86_64.rpm`) and Windows (`halyard-1.0.0-setup.exe`).

## Defaults

Everything finished is on: notifications, the MCP server, the offline queue. Remote images are blocked by default per message, with a Load images button, because loading them tells the sender you read the message; that is a privacy setting the person can turn on in Settings, not an unfinished feature.

## Proof that ran

* Unit tests: store (threads, search, snooze, undo send, outbox, contacts, threading), mime, discover, httpx retry, oauth PKCE and refresh, api (state lists, token and host checks).
* Live, with a real client of each kind: a Podman Stalwart server for IMAP, SMTP and JMAP (send, IDLE or EventSource delivery, attachments, full text search, threading, read, star, archive, trash, verified by a fresh client); a real Gmail mailbox (account@fireballz.ai); a real Microsoft 365 mailbox (account@fireballindustries.onmicrosoft.com).
* The MCP server driven by the official MCP client over HTTP with the bearer token, all 37 tools in groups, against the IMAP lab, the JMAP lab, Gmail and Microsoft 365.
* The UI in Chromium against a demo daemon (`ui/test/smoke.mjs`): threads, keyboard, search, composer, drafts, settings, MCP endpoint, no page errors.
* The Arch package and the openSUSE Tumbleweed rpm installed in VMs on The Beast, the app running in a kiosk compositor with WebKitGTK, an IMAP account added through the app's own MCP endpoint, lab mail listed. Screenshots in the codex under `work/out/mail/evidence/2026-11-22/`.

## Not proven

* **Windows:** the installer builds and is a PE file, but it has not been run on Windows. No Windows 11 media was available for a VM. WebView2 handling, the `mailto:` registration and uninstall are untested. The installer is **unsigned**: no code-signing certificate exists.
* **Browser sign-in for Google and Microsoft:** the OAuth loopback flow is tested against a stand-in token endpoint. The live proofs used a delegated Google token and a Microsoft password-grant token, not the in-app sign-in, because the product has no registered Google OAuth client or multi-tenant Entra application yet. Builds read `HALYARD_GOOGLE_CLIENT_ID`, `HALYARD_GOOGLE_CLIENT_SECRET` and `HALYARD_MS_CLIENT_ID`; without them the sign-in buttons say so.
* **Push:** Gmail and Graph updates arrive by polling (15 and 30 seconds). Their push channels need a public endpoint a desktop app does not have. IMAP uses IDLE and JMAP uses EventSource.
* **Drafts** are kept by the app on this computer and are not written to the provider's Drafts folder. A draft saved from the composer does not keep its attachments.
* **Desktop notifications** raise through the system but were not seen on a screen. Dark theme was not photographed in the native window.
* In the VMs only the first-run screen and the inbox were looked at; the composer, search, snooze and the rest were exercised in Chromium and in the live tests, not clicked in the VM.
* USPTO TSDR was not read for the name; checks were through aggregators.
* There are no calendar features and no calendar tools.

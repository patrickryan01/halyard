# Halyard 1.0.0

One release with everything in it. Nothing is behind a flag and nothing is left for a later release.

## What is in it

* **Accounts:** type an email address and the provider is found for you (known providers, MX records, Mozilla ISPDB, autoconfig, SRV). Microsoft 365, Outlook.com and Hotmail sign in with one click. Gmail and Google Workspace walk you through an app password on screen and work with nothing to register; a build that carries a Google client signs in with one click too. IMAP and SMTP, POP3 and JMAP for everything else. Several accounts, one combined inbox.
* **Reading:** conversations (or every message on its own), full text search with operators (`from:` `to:` `cc:` `bcc:` `subject:` `filename:` `label:` `in:` `is:` `has:` `before:` `after:` `older_than:` `newer_than:` `larger:` `smaller:`, phrases, exclusion and OR), saved searches, snooze, labels and folders, calendar invitations you answer from the message and add to a calendar, one click unsubscribe, read receipts, signature checks and decryption, print, view source, save as .eml or mbox. Remote images are held back until you allow them.
* **Writing:** rich text, attachments by button, drop and paste with a warning over 25 MB, drafts kept on the server, undo send, schedule for later, templates, several identities with their signatures and aliases, recipient suggestions, spell check, sign and encrypt with OpenPGP (RFC 3156) or S/MIME (RFC 8551), failed sends retried by themselves when the reason is temporary.
* **Organizing:** filters that run on new mail (conditions, actions, order, run now), server side filters over ManageSieve with the server's own checking, an automatic reply kept on the server (Gmail, Microsoft, JMAP, and IMAP through Sieve), create, rename and delete folders and labels, mark all read, empty trash and spam.
* **Contacts and calendar:** address books and calendars from any CardDAV and CalDAV server.
* **Moving in:** import an mbox file or a Thunderbird profile into folders of the account "On this computer".
* **Everywhere:** a command for every action with keyboard shortcuts you can change, a command palette, light and dark themes, an icon in the notification area, desktop notifications, an offline cache that replays your changes, a window that fits a phone width, and English plus Spanish, French, Italian, German, Norwegian Bokmal, Bulgarian, Greek, Korean, Japanese, Vietnamese, Hindi, Simplified Chinese and Arabic (right to left).
* **Automation:** the `halyard` command line (also `halyardctl`) and a read and write MCP server, on by default, with 87 tools that cover everything above. See `docs/MCP.md`.
* **Packages:** Arch (`halyard-1.0.0-1-x86_64.pkg.tar.zst`), EmberRTOS Desktop (openSUSE Tumbleweed, `halyard-1.0.0-0.x86_64.rpm`) and Windows (`halyard-1.0.0-setup.exe`, Authenticode signed; the build and the tag workflow refuse an unsigned installer). Each installs the program, the headless daemon and the command line, and registers the `mailto:` handler.

`docs/COMPLETENESS.md` lists every feature a full mail client has, with the automated check behind each row. Three rows are dropped on purpose, with the reason: RSS and newsgroup reading, an update check inside the app, and contact groups.

## Defaults

Everything finished is on: notifications, the tray icon, the MCP server, the offline queue. Remote images are blocked until you allow them, because loading one tells the sender you read the message; that is a privacy setting, not an unfinished feature.

## Proof that ran

* `tools/completeness.sh` on a test host: Go tests for every package, the live lab tests (a Podman Stalwart server for IMAP, SMTP, POP3, JMAP, ManageSieve, CalDAV and CardDAV), the browser tests (`ui/test/smoke.mjs`, `ui/test/features.mjs`, `ui/test/live_add.mjs`), the translation check for all thirteen languages, and the check of the list itself. The result is printed as COMPLETE.
* Live add account through the real window: an IMAP account, a Gmail style account by app password against the lab with a spaced password, a POP3 account, and a Microsoft account with a real sign in on login.microsoftonline.com.
* The MCP server driven by the official client over HTTP.
* The word check: `tools/no-ai-words.sh` finds none of the words it looks for in the tree, the history, or any commit message.

## Not proven

* **A real Google app password** was not made (it needs the account holder, who has two step verification on). The app password path is proved with a password login against the lab, and the Gmail IMAP and SMTP servers are proved with an access token over XOAUTH2.
* **Google one click sign in** needs a Google client built into the release; this build carries none, so Gmail uses the app password steps.
* **What only a person at a screen or a printer can see:** the Windows toast on screen, Linux desktop notifications, the tray icon on a real desktop, and paper from the printer. The calls are made and logged; the pictures were not reviewed.
* **Server messages** (the text a mail server sends back when it refuses something) stay in the server's language.
* **Push:** Gmail and Graph updates arrive by polling (15 and 30 seconds); their push channels need a public endpoint a desktop app does not have. IMAP uses IDLE and JMAP uses EventSource.
* **Signature trust:** the Windows installer is signed with a self signed certificate, so Windows shows an unknown publisher on a machine that has not been given the certificate. A purchased certificate replaces it later.

# Halyard 1.0.0

One release with everything in it.

## What is in it

* Google (Gmail API, OAuth, labels, threads, history sync, People contacts), Microsoft 365 and Outlook.com (Graph, OAuth, folders, delta sync, contacts), and self-hosted mail (IMAP with IDLE and SMTP, JMAP) as plugins behind one interface.
* Conversation threads, full text search with `from:`, `to:`, `subject:`, `is:unread`, `is:starred` and `has:attachment`, labels and folders, archive, delete, spam, snooze, undo send, drafts, a rich composer with attachments and drag and drop, signatures, a unified inbox, Gmail's keyboard shortcuts, desktop notifications, an offline cache with queued actions, contacts autocomplete, light and dark themes, and account setup from one field.
* A read and write MCP server, on by default, covering every account: 37 tools for accounts, folders, threads, search, send, reply, forward, drafts, the outbox, labels, archive, delete, snooze, attachments in and out, contacts, and settings. It needs a bearer token from the data directory and serves loopback only.
* Packages: Arch (`halyard-1.0.0-1-x86_64.pkg.tar.zst`), EmberRTOS Desktop (openSUSE Tumbleweed, `halyard-1.0.0-0.x86_64.rpm`) and Windows (`halyard-1.0.0-setup.exe`, Authenticode signed with the Fireball Industries self-signed code-signing certificate; the build and the tag workflow refuse an unsigned release).
* Sign-in apps are set up inside the app, on the account setup screen and under Settings: a person who brings their own Google or Microsoft client ID (and fixed port, if the app registers exact addresses) enters it once and it is kept. No script, chart or codex step.
* Drafts are saved to the provider's own Drafts folder (Gmail, Microsoft 365, IMAP, JMAP) and keep their attachments.

## Defaults

Everything finished is on: notifications, the MCP server, the offline queue. Remote images are blocked by default per message, with a Load images button, because loading them tells the sender you read the message; that is a privacy setting the person can turn on in Settings, not an unfinished feature.

## Proof that ran

* Unit tests: store (threads, search, snooze, undo send, outbox, contacts, threading), mime, discover, httpx retry, oauth PKCE and refresh, api (state lists, token and host checks), engine (new mail events, including a skewed server clock).
* Live, with a real client of each kind: a Podman Stalwart server for IMAP, SMTP and JMAP (send, IDLE or EventSource delivery, attachments, full text search, threading, read, star, archive, trash, drafts in the server's Drafts folder, verified by a fresh client); a real Gmail mailbox (account@fireballz.ai); a real Microsoft 365 mailbox (account@fireballindustries.onmicrosoft.com).
* The MCP server driven by the official MCP client over HTTP with the bearer token, all 37 tools in groups, against the IMAP lab, the JMAP lab, Gmail and Microsoft 365.
* Microsoft browser sign-in, live: the app registration "Halyard" (client id 5bc58f81-5155-4a3e-aedc-d6692de040c7, multi-tenant, `secrets/access/ms-halyard-app.sh`), the loopback flow, a Graph profile call and a token refresh, and the same flow inside the Arch VM with the packaged app.
* The UI in Chromium against a demo daemon (`ui/test/smoke.mjs`): threads, keyboard, search, composer, drafts with attachments, settings, MCP endpoint, theme following a change made elsewhere, no page errors.
* Arch package and openSUSE Tumbleweed rpm installed in VMs on The Beast, the app running in a kiosk compositor with WebKitGTK, mail listed, dark theme in the native window on Arch.
* Windows 11 Enterprise (evaluation) VM on The Beast with the signed installer: signature Valid after trusting the house certificate (UnknownError before, as for any self-signed certificate), timestamp verified; install, WebView2 present, `mailto:` handler registered and a link opened in the running window's composer, Start menu and Add or remove programs entries, first run, mail listed, new mail arriving, dark theme in the native window, uninstall removing the program and leaving the person's mail. Screenshots in the codex under `work/out/mail/evidence/2026-11-22/`.

## Not proven

* **Google browser sign-in with a built-in client:** this build carries no Google client. The Fireball staff client (`620446678028`, project embernet-488400) was probed on 2026-11-22 with Halyard's loopback addresses and refuses them (it only accepts its registered redirect addresses), so it needs one console change before staff sign in without bringing their own client: add `http://127.0.0.1:49157/callback`, `http://127.0.0.1:49158/callback` and `http://127.0.0.1:49159/callback` to its authorized redirect URIs, then build with `HALYARD_GOOGLE_CLIENT_ID`, `HALYARD_GOOGLE_CLIENT_SECRET` and `HALYARD_GOOGLE_PORTS=49157,49158,49159`. Until then a Google account signs in with the person's own Desktop client entered in the app. The Google plugin itself is proven live with a delegated token, and the loopback flow is the same code Microsoft's live sign-in exercised.
* **Windows desktop notification:** raised per the app log at 04:40:21 and 04:40:26 in the VM. The earlier hand test showed the toast on screen. The latest run's screenshots are unreviewed.
* **Linux desktop notifications** were not seen on a screen.
* **Push:** Gmail and Graph updates arrive by polling (15 and 30 seconds). Their push channels need a public endpoint a desktop app does not have. IMAP uses IDLE and JMAP uses EventSource.
* **Signature trust:** the certificate is self-signed, so Windows shows the publisher as unknown to a machine that has not been given the certificate (SmartScreen will warn). A purchased certificate replaces it when budget allows.
* In the Arch and Tumbleweed VMs only the first-run screen and the inbox were looked at; the rest was exercised in Chromium and in the live tests. Dark theme was seen in the native window on Arch and Windows, not on Tumbleweed.
* USPTO TSDR was not read for the name; checks were through aggregators. There is one live HALYARD Class 9 registration, for downloadable fonts.
* There are no calendar features and no calendar tools.
* The live tests leave a few labels and folders named `mcp-...` on the test mailboxes.
